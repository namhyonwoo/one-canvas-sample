# 유저 스토리: settlement-search (파트너가 기간별로 정산 내역을 검색한다)

## User Story
파트너가 정산 상태를 스스로 파악하기 위해, 조회 화면에서 기간을 지정해 자신의 정산 내역 목록을 검색한다.

> 기획 출처: `epic-partner-settlement-list` 참조 (캔버스 파일 경로는 에픽이 단일 출처)
> 대상 화면: 화면 1 `settlement-list (정산 내역 조회)` — 번호 영역 ①(조회 조건), ③(정산 내역 테이블), ④(페이지네이션)
> **구현 전 필수**: 위 화면을 캔버스에서 열어 배치·컴포넌트 태깅(story id)을 확인한다.
> 앵커·Figma 시안은 `epic-partner-settlement-list/index.md` 「참조 자료」에 있다 — 이 스토리는 배치·story id를 소유하지 않는다.

## 기능 정책

### 조회 조건 (①)
- 기간은 **시작일·종료일 2개 입력**으로 구성한다. 컴포넌트: `inputs/dateRangePicker`.
- 화면 진입 시 기간 기본값은 **최근 1개월**이다 (캔버스 예시: `2026-06-22 ~ 2026-07-22`).
- 조회는 **조회 버튼 클릭 시점에만** 실행된다. 기간 입력을 바꾸는 것만으로는 목록이 갱신되지 않는다.
  - 예외: 적용된 필터 칩의 × 클릭은 즉시 재조회한다 — 상세는 `story-settlement-filter` 참조.
- 조회 요청 중에는 조회 버튼을 **비활성 처리하고 라벨을 `조회중...`으로** 바꿔 중복 요청을 막는다. 응답 후 `조회`로 원복한다.

### 정산 내역 테이블 (③)
- 컬럼은 **정산일 / 파트너명 / 금액 / 상태** 4개다. 컴포넌트: `display/table`, 상태 값은 `display/tag`.
- 정렬 기본값은 **정산일 내림차순**(최신 건이 위)이다.
- 행에 hover 하면 하이라이트되고 커서가 포인터로 바뀐다. 행 클릭 시 동작은 `story-settlement-detail` 참조.
- 조회 결과가 0건이면 목록 행 대신 **`조건에 맞는 정산 내역이 없습니다`** 안내 행을 테이블 본문 전체 폭에 가운데 정렬로 표시한다. 이 안내 행은 hover 하이라이트·클릭 진입이 모두 비활성이다.

### 페이지네이션 (④)
- 페이지당 **3건**씩 표시한다.
- 조회 결과가 **3건을 초과할 때만** 페이지네이션을 노출한다.
- 구성: `이전` + 페이지 번호 + `다음`. 컴포넌트: `display/pagination`.
- 첫 페이지에서는 `이전`이, 마지막 페이지에서는 `다음`이 비활성이다.
- 페이지 전환 시 **테이블 본문만 갱신**되고 조회 조건(①)·적용된 필터(②) 영역은 유지된다.
- 조회 조건을 바꿔 재조회하면 현재 페이지는 **1페이지로 초기화**된다.

> 금액·일자 표기 규칙: `settlement/index.md` 참조 · 정산 상태 3종 정의: `epic-partner-settlement-list/index.md` 참조

### 열린 질문 (기획 확인 필요)
- 시작일이 종료일보다 늦은 경우의 처리(입력 차단 / 조회 시 에러 안내)는 캔버스에 정의되어 있지 않다. 확정 후 AC·태스크를 보강한다.
- 조회 가능한 최대 기간 범위(예: 최대 1년) 제한 여부가 캔버스에 없다. 확정 필요.

## 수락 기준 (Acceptance Criteria)
> Given-When-Then 시나리오로 작성한다. 정상/예외 등 조건 분기는 시나리오를 분리한다.

- [ ] **AC1** Given 정산 내역이 있는 파트너가 조회 화면에 있고, When 시작일·종료일을 선택해 조회 버튼을 누르면, Then 해당 기간에 속하는 정산 내역만 목록에 표시된다.
- [ ] **AC2** (보강) Given 파트너가 조회 화면에 처음 진입했고, When 아직 어떤 조건도 변경하지 않았으면, Then 기간이 최근 1개월 기본값으로 채워진 상태로 초기 목록이 표시된다.
- [ ] **AC3** Given 선택한 기간에 정산 내역이 없고, When 조회하면, Then 목록 대신 `조건에 맞는 정산 내역이 없습니다` 안내 행을 보여준다.
- [ ] **AC4** (보강) Given 결과 없음 안내 행이 표시된 상태에서, When 그 행에 hover 하거나 클릭하면, Then 행 하이라이트와 상세 진입이 모두 동작하지 않는다.
- [ ] **AC5** (보강) Given 조회 요청을 보낸 직후이고, When 응답이 아직 도착하지 않았으면, Then 조회 버튼이 비활성 + `조회중...` 라벨로 바뀌어 추가 클릭을 받지 않는다.
- [ ] **AC6** (보강) Given 조회 응답이 도착했고, When 목록 렌더링이 끝나면, Then 조회 버튼이 활성 + `조회` 라벨로 원복된다.
- [ ] **AC7** (보강) Given 조회 결과가 3건을 초과하고, When 목록이 렌더링되면, Then 페이지당 3건씩 표시되고 페이지네이션이 노출된다.
- [ ] **AC8** (보강) Given 조회 결과가 3건 이하이고, When 목록이 렌더링되면, Then 페이지네이션이 노출되지 않는다.
- [ ] **AC9** (보강) Given 2페이지 이상의 결과가 있고, When 다른 페이지 번호를 클릭하면, Then 테이블 본문만 해당 페이지 내용으로 갱신되고 조회 조건·적용된 필터 영역은 그대로 유지된다.
- [ ] **AC10** (보강) Given 1페이지를 보고 있고, When 페이지네이션을 확인하면, Then `이전` 버튼이 비활성 상태다.
- [ ] **AC11** (보강) Given 마지막 페이지를 보고 있고, When 페이지네이션을 확인하면, Then `다음` 버튼이 비활성 상태다.
- [ ] **AC12** (보강) Given 2페이지 이상을 보고 있는 상태에서, When 조회 조건을 바꿔 다시 조회하면, Then 목록이 1페이지부터 다시 표시된다.
- [ ] **AC13** (보강) Given 여러 정산 건이 조회되었고, When 목록을 확인하면, Then 정산일 내림차순으로 정렬되어 있고 금액은 천 단위 콤마 + `원` 형식으로 표기된다.

## 테스트 (QA Role)

### 성공
- 기간을 `2026-07-01 ~ 2026-07-20`으로 지정하고 조회 → 해당 기간 정산 건만 목록에 표시된다. (AC1)
- 화면 첫 진입 → 기간이 최근 1개월로 채워져 있고 초기 목록이 이미 렌더링되어 있다. (AC2)
- 조회 버튼 클릭 직후 → 버튼이 눌리지 않는 상태로 `조회중...`이 표시된다. (AC5)
- 응답 수신 후 → 버튼이 `조회`로 돌아오고 다시 클릭 가능하다. (AC6)
- 6건이 조회되는 조건으로 조회 → 1페이지에 3건 표시 + 페이지네이션(1, 2) 노출. (AC7)
- 2건만 조회되는 조건으로 조회 → 2건 표시 + 페이지네이션 미노출. (AC8)
- 2페이지 클릭 → 테이블 내용만 바뀌고 기간 입력값·상태 체크·필터 칩은 그대로다. (AC9)
- 1페이지 상태에서 `이전` 버튼이 비활성이다. (AC10)
- 마지막 페이지에서 `다음` 버튼이 비활성이다. (AC11)
- 2페이지를 보다가 기간을 바꿔 재조회 → 1페이지부터 표시된다. (AC12)
- 목록 첫 행이 가장 최근 정산일이고, 금액이 `1,204,000원` 형태로 표기된다. (AC13)

### 실패 (예외처리 포함)
- 정산 건이 하나도 없는 기간으로 조회 → 빈 테이블이 아니라 `조건에 맞는 정산 내역이 없습니다` 안내 행이 표시된다. (AC3)
- 결과 없음 안내 행에 마우스를 올림 → 배경색이 바뀌지 않고 커서가 포인터로 바뀌지 않는다. (AC4)
- 결과 없음 안내 행을 클릭 → 상세 모달이 열리지 않는다. (AC4)
- 조회 응답 도착 전 조회 버튼을 연타 → 추가 요청이 발생하지 않는다. (AC5)
- 조회 API가 5xx로 실패 → 에러 안내가 노출되고, 조회 버튼은 `조회`로 원복되어 재시도가 가능하다. (AC6)
