# 유저 스토리: settlement-filter (파트너가 정산 상태로 내역을 필터링한다)

## User Story
파트너가 지급이 밀린 건이나 확인이 필요한 건을 빠르게 골라내기 위해, 정산 상태(대기/완료/보류)로 목록을 좁혀서 본다.

> 기획 출처: `epic-partner-settlement-list` 참조 (캔버스 파일 경로는 에픽이 단일 출처)
> 대상 화면: 화면 1 `settlement-list (정산 내역 조회)` — 번호 영역 ①(상태 체크박스), ②(적용된 필터)
> **구현 전 필수**: 위 화면을 캔버스에서 열어 배치·컴포넌트 태깅(story id)을 확인한다.
> 앵커·Figma 시안은 `epic-partner-settlement-list/index.md` 「참조 자료」에 있다 — 이 스토리는 배치·story id를 소유하지 않는다.

## 기능 정책

### 상태 필터 (①)
- 상태는 **대기 / 완료 / 보류** 3종을 체크박스로 제공한다. 컴포넌트: `inputs/checkbox`.
- **다중 선택 가능**하며, 여러 개를 선택하면 **OR 조건**으로 조회한다 (선택한 상태 중 하나라도 일치하는 건).
- 화면 진입 시 기본값은 **`완료`만 체크**된 상태다.
- 상태를 **하나도 선택하지 않으면 전체 상태를 조회**한다 (= 상태 조건 미적용). "0건 조회"가 아니다.
- 체크박스 변경만으로는 목록이 갱신되지 않고, 조회 버튼을 눌러야 반영된다 (조회 트리거 정책은 `story-settlement-search` 참조).

### 적용된 필터 (②)
- 마지막으로 **조회에 실제 사용된 조건**을 칩으로 보여준다. 체크만 하고 조회하지 않은 조건은 칩에 반영되지 않는다. 컴포넌트: `inputs/filterChip`.
- 칩 구성:
  - **기간 칩** 1개 — `기간: {시작일} ~ {종료일}`. 기간은 필수 조건이므로 **제거(×) 버튼이 없다.**
  - **상태 칩** N개 — `상태: {상태명}`. 선택된 상태 수만큼 생성되며 각각 **제거(×) 버튼이 있다.**
- 상태 칩의 × 클릭 → 해당 상태 체크박스만 해제하고 **즉시 재조회**한다 (조회 버튼을 다시 누를 필요 없음).
- 마지막 남은 상태 칩을 × 로 제거하면 상태 조건이 전부 해제되므로 **전체 상태 목록**이 조회된다.
- 재조회 결과에 맞춰 칩 목록도 다시 렌더링된다.

### 허용 상태 값
- 조회에 사용할 수 있는 상태 값은 **대기 / 완료 / 보류 3종뿐**이다.
- 그 외의 값이 조회 파라미터로 전달되면 목록을 조회하지 않고 **검증 에러로 처리**한다. 알 수 없는 값을 무시하고 조회를 진행하지 않는다.

> 정산 상태 3종 정의: `epic-partner-settlement-list/index.md` 참조 · 조회 트리거·페이지네이션 정책: `story-settlement-search` 참조

## 수락 기준 (Acceptance Criteria)
> Given-When-Then 시나리오로 작성한다. 정상/예외 등 조건 분기는 시나리오를 분리한다.

- [ ] **AC1** (보강) Given 파트너가 조회 화면에 처음 진입했고, When 상태 필터 영역을 확인하면, Then `완료`만 체크되어 있고 `대기`·`보류`는 해제되어 있다.
- [ ] **AC2** Given 정산 내역 목록이 표시된 상태에서, When 상태 필터로 `보류` 하나만 선택해 조회하면, Then 상태가 `보류`인 내역만 목록에 남는다.
- [ ] **AC3** Given 정산 내역 목록이 표시된 상태에서, When 상태 필터로 `대기`와 `보류`를 함께 선택해 조회하면, Then 두 상태 중 하나에 해당하는 내역이 모두 목록에 표시된다.
- [ ] **AC4** (보강) Given 모든 상태 체크박스가 해제된 상태에서, When 조회하면, Then 상태 조건 없이 전체 상태의 정산 내역이 조회된다.
- [ ] **AC5** (보강) Given `대기`와 `완료`를 선택해 조회한 직후, When 적용된 필터 영역을 확인하면, Then 기간 칩 1개와 상태 칩 2개(`상태: 대기`, `상태: 완료`)가 표시된다.
- [ ] **AC6** (보강) Given 적용된 필터에 상태 칩 2개가 있고, When `상태: 대기` 칩의 × 를 클릭하면, Then `대기` 체크박스가 해제되고 조회 버튼을 누르지 않아도 즉시 재조회되어 `완료` 건만 남는다.
- [ ] **AC7** (보강) Given 적용된 필터에 상태 칩이 1개만 남아 있고, When 그 칩의 × 를 클릭하면, Then 상태 조건이 전부 해제되어 전체 상태의 목록이 조회된다.
- [ ] **AC8** (보강) Given 적용된 필터 영역이 표시된 상태에서, When 기간 칩을 확인하면, Then 기간 칩에는 제거(×) 버튼이 없어 제거할 수 없다.
- [ ] **AC9** (보강) Given 상태 체크박스를 변경했고, When 아직 조회 버튼을 누르지 않았으면, Then 목록과 적용된 필터 칩은 직전 조회 결과 그대로 유지된다.
- [ ] **AC10** (보강) Given 선택한 상태 조합에 해당하는 정산 건이 없고, When 조회하면, Then 결과 없음 안내가 표시된다. (상세 동작은 `story-settlement-search` AC3 참조)
- [ ] **AC11** (보강) Given 대기/완료/보류 외의 상태 값이 조회 파라미터로 전달되었고, When 조회를 요청하면, Then 목록을 조회하지 않고 검증 에러로 처리된다.

## 테스트 (QA Role)

### 성공
- 화면 첫 진입 → `완료`만 체크되어 있다. (AC1)
- `보류`만 체크하고 조회 → 상태가 `보류`인 건만 목록에 남는다. (AC2)
- `대기`+`보류`를 체크하고 조회 → 두 상태의 건이 모두 표시되고 `완료` 건은 보이지 않는다. (AC3)
- 모든 체크박스를 해제하고 조회 → 대기/완료/보류 건이 모두 표시된다. (AC4)
- `대기`+`완료` 조회 후 → 칩이 `기간: 2026-06-22 ~ 2026-07-22`, `상태: 대기`, `상태: 완료` 3개로 표시된다. (AC5)
- `상태: 대기` 칩의 × 클릭 → 조회 버튼을 누르지 않았는데 목록이 즉시 `완료` 건만 남도록 갱신되고, 칩도 2개로 줄어든다. (AC6)
- 마지막 상태 칩의 × 클릭 → 전체 상태 목록으로 갱신되고 상태 칩이 모두 사라진다. (AC7)

### 실패 (예외처리 포함)
- 기간 칩에서 × 를 찾아 클릭 시도 → × 버튼 자체가 존재하지 않아 기간 조건은 제거할 수 없다. (AC8)
- 상태 체크박스만 바꾸고 조회 버튼을 누르지 않음 → 목록과 칩이 이전 조회 결과 그대로 유지된다. (AC9)
- 해당 건이 하나도 없는 상태 조합(예: `보류`만 선택했는데 보류 건 없음)으로 조회 → 결과 없음 안내 행이 표시되고 칩은 정상 렌더링된다. (AC10)
- 허용되지 않은 상태 값을 파라미터로 직접 조작해 요청 → 서버가 검증 에러를 반환하고 목록이 잘못 조회되지 않는다. (AC11)
