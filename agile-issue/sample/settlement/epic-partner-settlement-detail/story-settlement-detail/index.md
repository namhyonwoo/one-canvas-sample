# 유저 스토리: settlement-detail (파트너가 특정 건의 정산 상세를 확인한다)

## User Story
파트너가 정산 금액이 왜 그 금액인지 스스로 납득하기 위해, 목록에서 특정 정산 건을 열어 산출 근거(판매액/수수료/조정 금액/최종 정산액)를 확인한다.

> 기획 출처: `epic-partner-settlement-detail` 참조 (캔버스 파일 경로는 에픽이 단일 출처)
> 대상 화면: 화면 1 `settlement-detail-modal (정산 상세 모달)` — 번호 영역 ①②  /  화면 2 `settlement-detail-page (정산 상세 페이지형)` — **대안 UI**, 번호 영역 ①②③
> **구현 전 필수**: 위 화면을 캔버스에서 열어 배치·컴포넌트 태깅(story id)을 확인한다.
> 앵커·Figma 시안은 `epic-partner-settlement-detail/index.md` 「참조 자료」에 있다 — 이 스토리는 배치·story id를 소유하지 않는다.

## 기능 정책

### 진입 경로
- **기본**: 화면 1의 상세 진입점(정산 내역 행)을 클릭하면 상세 **모달**이 열린다. 목록 조회·필터·페이지네이션 정책은 이 스토리 범위가 아니다 — `epic-partner-settlement-list` 참조. 컴포넌트: `feedback/modal`.
- **대안 UI**: 화면 2 `settlement-detail-page` 페이지형. 동일한 산출 근거를 페이지 전체로 보여주며, 모달에 없는 액션(목록으로 / 정산내역 다운로드)을 제공한다.
- 두 UI 모두 **같은 정산 상세 데이터**를 사용한다. 화면마다 다른 계산 결과를 보여주지 않는다.
- 결과 없음 안내 행은 클릭해도 상세가 열리지 않는다 (`story-settlement-search` 참조).

### 상세 모달 (화면 1)
- 타이틀: `{정산일} 정산 상세` (예: `2026-07-20 정산 상세`).
- 본문 항목 (`display/infoField` 나열):
  1. 파트너명
  2. 상품 판매액
  3. 플랫폼 수수료
  4. 조정 금액
  5. 최종 정산액
- 닫기 경로 4종을 모두 지원한다: **닫기 버튼 / 헤더 ✕ / 배경(backdrop) 클릭 / ESC 키**.
- 모달 박스 **내부** 클릭은 닫히지 않는다.
- 상태가 `보류`인 건은 최종 정산액 값에 보류임을 함께 표기한다 (캔버스 예시: `410,300원(보류)`).

### 상세 페이지형 (화면 2, 대안 UI)
- ① 타이틀 — `정산 상세 — {정산일} ({파트너명})`. 컴포넌트: `display/subTitle`.
- ② 산출 근거 — `display/infoField` **3열 그리드**로 6개 항목 배치: 파트너명 / 정산 기간 / 상품 판매액 / 플랫폼 수수료 / 조정 금액 / 최종 정산액.
  - 플랫폼 수수료에는 보조 문구로 **수수료율**(예: `수수료율 10%`)을 표시한다.
  - 조정 금액에는 보조 문구로 **조정 사유**(예: `반품 1건 반영`)를 표시한다. 조정이 없으면 보조 문구를 생략한다.
- 액션 영역 앞에 구분선을 둔다. 컴포넌트: `display/divider`.
- ③ 액션 버튼 2종. 컴포넌트: `inputs/button`.
  - `목록으로` (variant=secondaryGray) — 정산 내역 목록으로 이동한다.
  - `정산내역 다운로드` (variant=primary, size=lg) — 정산 내역서 파일 다운로드를 시작하고 **`다운로드가 시작되었습니다`** 안내를 노출한 뒤 자동으로 사라진다.

### 상세 조회 실패 처리
- 파트너 **본인 소유가 아닌** 정산 건 ID로 상세를 요청하면 상세를 노출하지 않고 **접근을 거부**한다 (도메인 정책 「조회 주체와 데이터 범위」).
- **존재하지 않는** 정산 건 ID로 요청하면 빈 내용의 상세를 열지 않고 **에러 안내**를 노출한다.
- 상세 조회 또는 다운로드 요청이 실패하면 화면이 깨진 상태로 남지 않게 **에러 안내를 노출**하고, 모달의 경우 **닫기 경로를 유지**한다.

> 정산 금액 산출 공식·금액 표기 규칙: `settlement/index.md` 참조 · 정산 상태 3종 정의: `epic-partner-settlement-detail/index.md` 참조

### 열린 질문 (기획 확인 필요)
- 다운로드 안내 문구가 캔버스에서 `<!-- component: X -->` 태깅 없이 구현되어 있다. `feedback/toast` 컴포넌트를 사용할지 확정 필요 — 태깅 누락 요소는 임의 구현하지 않는다(도메인 정책 「디자인 시스템 재사용 원칙」).
- 정산 내역서 다운로드 **파일 포맷(PDF/Excel)과 포함 항목**이 캔버스에 정의되어 있지 않다. 확정 후 백엔드 태스크를 보강한다.
- 화면 2(페이지형)가 모달을 **대체**하는지 **병행 제공**하는지 캔버스에 명시가 없다. 본 스토리는 병행 제공 전제로 작성했다.

## 수락 기준 (Acceptance Criteria)
> Given-When-Then 시나리오로 작성한다. 정상/예외 등 조건 분기는 시나리오를 분리한다.

### 상세 모달 (화면 1)
- [ ] **AC1** Given 정산 내역 목록이 표시된 상태에서, When 특정 정산 행을 클릭하면, Then 해당 건의 정산 상세 모달이 열린다.
- [ ] **AC2** (보강) Given 상세 모달이 열렸고, When 타이틀을 확인하면, Then `{해당 건 정산일} 정산 상세` 형식으로 표시된다.
- [ ] **AC3** Given 상세 모달이 열렸고, When 본문을 확인하면, Then 파트너명·상품 판매액·플랫폼 수수료·조정 금액·최종 정산액이 순서대로 표시된다.
- [ ] **AC4** (보강) Given 상세 모달이 열렸고, When 표시된 금액을 검산하면, Then `최종 정산액 = 상품 판매액 − 플랫폼 수수료 − 조정 금액`이 성립한다.
- [ ] **AC5** (보강) Given 상세 모달이 열려 있고, When `닫기` 버튼을 클릭하면, Then 모달이 닫히고 목록 화면으로 돌아간다.
- [ ] **AC6** (보강) Given 상세 모달이 열려 있고, When 헤더의 ✕ 를 클릭하면, Then 모달이 닫힌다.
- [ ] **AC7** (보강) Given 상세 모달이 열려 있고, When 모달 바깥 배경을 클릭하면, Then 모달이 닫힌다.
- [ ] **AC8** (보강) Given 상세 모달이 열려 있고, When ESC 키를 누르면, Then 모달이 닫힌다.
- [ ] **AC9** (보강) Given 상세 모달이 열려 있고, When 모달 박스 내부의 빈 영역을 클릭하면, Then 모달이 닫히지 않고 그대로 유지된다.
- [ ] **AC10** (보강) Given 상태가 `보류`인 정산 건이고, When 상세 모달을 열면, Then 최종 정산액에 보류 상태임이 함께 표기된다.
- [ ] **AC11** (보강) Given 상세 모달을 닫았고, When 목록을 확인하면, Then 조회 조건·적용된 필터·현재 페이지가 모달을 열기 전 상태 그대로 유지된다.

### 상세 페이지형 (화면 2, 대안 UI)
- [ ] **AC12** (보강) Given 정산 상세 페이지에 진입했고, When 타이틀을 확인하면, Then `정산 상세 — {정산일} ({파트너명})` 형식으로 표시된다.
- [ ] **AC13** (보강) Given 정산 상세 페이지에 진입했고, When 산출 근거 영역을 확인하면, Then 파트너명·정산 기간·상품 판매액·플랫폼 수수료·조정 금액·최종 정산액 6개 항목이 3열 그리드로 표시된다.
- [ ] **AC14** (보강) Given 정산 상세 페이지에 진입했고, When 플랫폼 수수료 항목을 확인하면, Then 적용된 수수료율이 보조 문구로 함께 표시된다.
- [ ] **AC15** (보강) Given 조정 금액이 발생한 정산 건이고, When 상세 페이지를 확인하면, Then 조정 사유가 보조 문구로 함께 표시된다.
- [ ] **AC16** (보강) Given 조정 금액이 `0원`인 정산 건이고, When 상세 페이지를 확인하면, Then 조정 금액은 `0원`으로 표시되고 조정 사유 보조 문구는 표시되지 않는다.
- [ ] **AC17** (보강) Given 정산 상세 페이지에 있고, When `목록으로` 버튼을 클릭하면, Then 정산 내역 목록으로 이동한다.
- [ ] **AC18** Given 정산 상세 페이지에 있고, When `정산내역 다운로드` 버튼을 클릭하면, Then 다운로드가 시작되고 `다운로드가 시작되었습니다` 안내가 노출된다.
- [ ] **AC19** (보강) Given 다운로드 안내가 노출된 뒤, When 일정 시간이 지나면, Then 안내가 자동으로 사라진다.

### 조회 실패
- [ ] **AC20** (보강) Given 파트너 본인 소유가 아닌 정산 건 ID이고, When 해당 건의 상세를 요청하면, Then 상세가 노출되지 않고 접근이 거부된다.
- [ ] **AC21** (보강) Given 존재하지 않는 정산 건 ID이고, When 해당 건의 상세를 요청하면, Then 빈 내용의 상세가 열리지 않고 에러 안내가 노출된다.
- [ ] **AC22** (보강) Given 상세 조회 요청이 실패했고, When 상세 모달을 확인하면, Then 에러 안내가 노출되고 닫기 경로(닫기/✕/배경/ESC)는 그대로 동작한다.
- [ ] **AC23** (보강) Given `정산내역 다운로드` 요청이 실패했고, When 결과를 확인하면, Then `다운로드가 시작되었습니다` 안내 대신 실패 안내가 노출된다.

- ESC 키 입력 → 모달이 닫힌다. (AC8)
- 모달을 열었다 닫은 뒤 → 기간 입력값·상태 체크·필터 칩·페이지 번호가 그대로다. (AC11)
- 상세 페이지 타이틀이 `정산 상세 — 2026-07-20 (스타일셀러)`로 표시된다. (AC12)
- 상세 페이지에 6개 항목이 3열 그리드로 표시된다. (AC13)
- 플랫폼 수수료 아래에 `수수료율 10%` 보조 문구가 표시된다. (AC14)
- 조정 금액 아래에 `반품 1건 반영` 보조 문구가 표시된다. (AC15)
- `목록으로` 클릭 → 정산 내역 목록으로 이동한다. (AC17)
- `정산내역 다운로드` 클릭 → 다운로드가 시작되고 `다운로드가 시작되었습니다` 안내가 노출된다. (AC18)
- 안내 노출 후 일정 시간이 지나면 자동으로 사라진다. (AC19)

### 실패 (예외처리 포함)
- 모달 박스 내부 빈 영역을 클릭 → 모달이 닫히지 않는다. (AC9)
- 상태가 `보류`인 건(`2026-07-05 / 그린라이프`)의 상세를 열면 → 최종 정산액에 보류 표기가 함께 나타나, 완료 건과 구분된다. (AC10)
- 조정 금액이 `0원`인 건의 상세 페이지 → 조정 사유 보조 문구가 표시되지 않는다(빈 문구가 자리만 차지하지도 않는다). (AC16)
- 타 파트너의 정산 건 ID로 상세를 직접 요청 → 상세가 노출되지 않고 접근 거부 처리된다. (AC20)
- 존재하지 않는 정산 건 ID로 요청 → 모달이 빈 내용으로 열리지 않고 에러 안내가 노출된다. (AC21)
- 상세 조회 API가 실패 → 모달이 깨진 상태로 남지 않고 에러 안내와 닫기 경로가 유지된다. (AC22)
- 다운로드 API가 실패 → `다운로드가 시작되었습니다` 안내가 노출되지 않고 실패 안내가 표시된다. (AC23)
