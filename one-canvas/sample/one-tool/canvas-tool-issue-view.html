one-tool 이슈 보기

문서 종류: 통합캔버스 · 작성 기준: one-canvas/one-canvas-rule.md 참조 · 화면 목업의 버튼·트리·전환은 실제 동작하는 인터랙션 데모입니다.

전제 1 — 디자인 시스템 미사용: 이 캔버스는 요청에 따라 design-system을 사용하지 않는다. 따라서 컴포넌트명 + story id 태깅을 두지 않고, 그 자리에 각 영역이 쓰는 one-tool 자체 소유 마크업(page-local)을 적는다. 대상 화면이 사내 업무툴(one-tool)이고 design-system/admin-partner·design-system/app 어느 쪽의 대상도 아니기 때문이다.
전제 2 — 파일명 플랫폼 토큰: 파일명 규칙의 플랫폼 값(admin/partner/app) 중 해당하는 것이 없어 사내 업무툴을 뜻하는 tool을 썼다 — 규칙에 없는 값이므로 확정 필요.
전제 3 — 폴더 위치: 규칙상 sample/은 예시 전용이지만, 요청에 따라 one-canvas/sample/one-tool/에 둔다.

참고 자료

에픽

에픽epic-tool-issue-view (one-tool 이슈 보기)
목적기획(통합캔버스)과 개발 이슈(애자일 이슈)가 서로 다른 도구에 흩어져 있어 대조에 비용이 드는 문제를 없앤다. 레포에 파일로 관리되는 애자일 이슈를 one-tool 안에서 열람하게 하고, 캔버스 보기와 이슈 보기를 한 번의 클릭으로 오갈 수 있게 해 같은 화면에서 기획과 이슈를 맞춰볼 수 있게 한다.
주요 범위 (In-Scope) 좌측 사이드의 이슈 계층 트리(도메인 → 에픽 → 스토리) · 도메인·에픽 노드 접기/펼치기 · 에픽 클릭 시 본문에 제목·목적 랜딩 · 스토리 클릭 시 본문에 제목·상태·설명·수락 기준·태스크·테스트 랜딩 · 최상단 네비게이션 바 좌측 상단의 뷰 스위처로 캔버스 보기 ↔ 이슈 보기 전환 · 마지막으로 본 모드로 복귀 · 진입 시 트리 전부 접힘 + 본문 빈 안내
제외 범위 (Out-of-Scope) 이슈 문서 편집·상태 변경(열람 전용 — 요구사항에 없음) · 이슈 본문에 코멘트 달기(코멘트는 캔버스 보기의 기능이며 요구사항에 없음) · 도메인 노드 클릭 시 본문 랜딩(요구사항은 에픽·스토리 클릭만 정의) · 이슈 검색·필터·정렬(요구사항에 없음) · 규칙 예시용 sample 도메인 노출(제외 — 실무 이슈와 섞이면 목록이 오염된다) · 모드 전환 시 직전에 보던 이슈·캔버스 복원(복귀 대상은 모드까지)
완료 기준사용자가 이슈 보기를 열어 도메인 → 에픽 → 스토리를 펼쳐 내려가고, 에픽에서 제목·목적을, 스토리에서 제목·상태·설명·수락 기준·태스크·테스트를 확인할 수 있어야 한다. 또 뷰 스위처로 캔버스 보기와 이슈 보기를 오간 뒤 새로고침해도 마지막으로 본 모드로 돌아와야 한다.

유저스토리

  • story-issue-tree-browse (기획자·개발자가 이슈 전체 계층을 훑어 원하는 이슈를 찾는다)
    • Given 레포에 애자일 이슈 문서가 있고, When 이슈 보기를 열면, Then 좌측 사이드에 도메인 → 에픽 → 스토리가 계층으로 표시된다.
    • Given 이슈 보기에 처음 진입했고, When 화면을 보면, Then 트리는 전부 접힌 상태이고 본문에는 이슈를 선택하라는 안내가 표시된다.
    • Given 도메인 노드가 접혀 있고, When 도메인을 클릭하면, Then 하위 에픽이 펼쳐지고 다시 클릭하면 접힌다.
  • story-issue-epic-landing (개발자가 에픽의 목적을 확인해 작업 범위를 파악한다)
    • Given 트리에 에픽이 표시된 상태에서, When 에픽을 클릭하면, Then 본문에 그 에픽의 제목과 목적이 표시된다.
    • Given 에픽을 클릭했고, When 트리를 보면, Then 그 에픽의 하위 스토리가 펼쳐져 다음에 열 스토리를 바로 고를 수 있다.
  • story-issue-story-landing (개발자·QA가 스토리 명세를 한 화면에서 확인해 착수·검증한다)
    • Given 트리에 스토리가 표시된 상태에서, When 스토리를 클릭하면, Then 본문에 제목·상태·설명·수락 기준·태스크·테스트가 표시된다.
    • Given 스토리를 열었고, When 태스크 영역을 보면, Then 문서에 적힌 Role 구분과 라인별 진행 상태가 그대로 표시된다.
  • story-view-switch (사용자가 캔버스 보기와 이슈 보기를 오가며 기획과 이슈를 대조한다)
    • Given 캔버스 보기를 보고 있고, When 최상단 네비게이션 바 좌측 상단의 뷰 스위처에서 이슈를 선택하면, Then 이슈 보기로 전환된다.
    • Given 이슈 보기를 보고 있고, When 뷰 스위처에서 캔버스를 선택하면, Then 캔버스 보기로 돌아간다.
    • Given 이슈 보기를 보다가 페이지를 다시 열었고, When 화면이 로드되면, Then 마지막으로 본 모드인 이슈 보기로 복귀한다.

화면(디자인)

화면 위 번호는 UI 디스크립션의 번호와 1:1로 대응한다. 화면 1·2는 같은 3단 레이아웃의 서로 다른 랜딩 상태이며, 번호는 그 화면이 소유하는 영역에만 붙였다(공유 영역은 화면 1이 소유한다). 화면 3은 전환 자체를 확인하는 축약 화면이라 헤더와 두 모드의 골격만 담았다.

디스크립션은 유형에 따라 자리가 갈린다 — 화면설명은 화면 바로 아래에 그대로 보이며 페이지 설명과 규칙·데이터 출처·권한·예외를 담고, UI 디스크립션은 우측 플로팅 패널에 뜨며 번호로 지목한 영역·인터랙션·page-local 마크업을 담는다. 이 캔버스는 디자인 시스템을 쓰지 않으므로(전제 1) 태깅 자리에는 story id 대신 one-tool 자체 소유 마크업 위치를 적는다.

목업의 이슈 데이터는 레포의 실제 agile-issue/partner-review 문서(에픽 5개 · 스토리 23개의 실제 이름과 상태)에서 가져왔다. 스토리 본문 전문은 분량 때문에 story-admin-detail-history 1건만 담았고(수락 기준·태스크·테스트는 앞 몇 줄만), 나머지 스토리는 제목·상태까지만 담았다.

    화면설명 — issue-view-epic (이슈 보기 — 에픽 랜딩)

    • 페이지 목적 — 레포에 파일로 관리되는 애자일 이슈를 one-tool 안에서 계층째로 훑고, 에픽 단위 작업 범위를 확인하는 화면이다.
    • 데이터 출처 — 트리와 본문은 레포 agile-issue 디렉터리의 이슈 문서를 근거로 표시한다. 이슈를 별도로 옮겨 적어두지 않는다 — 캔버스·이슈의 최신성이 이 화면의 전제다.
    • 계층 기준 — 도메인 → 에픽 → 스토리 3계층이며, 애자일 이슈의 디렉터리 계층이 그대로 트리 계층이다. 계층을 화면에서 새로 정의하지 않는다.
    • 노출 범위 — 규칙 예시용 sample 도메인은 트리에 노출하지 않는다. 실무 이슈와 섞이면 목록이 오염된다.
    • 진입 상태 — 이슈 보기에 진입하면 트리는 전부 접혀 있고 본문에는 선택 안내만 둔다. 이슈 수가 많아 특정 도메인을 목표로 들어오는 경우가 많으므로 자동 선택하지 않는다.
    • 클릭 대상별 역할 — 도메인은 하위 계층을 여닫는 역할만 하고 본문 랜딩 대상이 아니다. 에픽은 본문 랜딩과 하위 스토리 펼침을 함께 한다.
    • 에픽 본문 표시 항목 — 제목(영문명 + 한글명)과 목적 두 가지다. 범위·완료 기준·흐름도 등 다른 에픽 항목은 이 범위에서 표시하지 않는다.
    • 권한 — 열람 전용이다. 이슈 문서의 내용·상태를 이 화면에서 바꾸지 않는다.
    • 미정 — 확정 필요: 이슈 문서가 없거나 형식을 벗어나 읽을 수 없을 때의 표기(빈 상태 문구 / 오류 안내 / 해당 노드 처리)는 요구사항에 근거가 없어 정의하지 않았다. 지어내지 않고 남겨둔다.

      화면설명 — issue-view-story (이슈 보기 — 스토리 랜딩)

      • 페이지 목적 — 스토리 하나를 착수·검증할 수 있을 만큼의 명세를 스크롤 한 번으로 읽는 화면이다. 문서를 파일로 직접 열지 않아도 되게 한다.
      • 표시 항목 — 제목 · 상태 · 설명 · 수락 기준 · 태스크 · 테스트 6가지를 표시한다. 이 6가지가 스토리 랜딩의 범위다.
      • 상태 표기 — 문서에 기록된 진행 상태를 그대로 보여준다. 상태 값 체계(작성 중 / 착수 가능 / 개발 중 / 완료 / 완료 후 기획 변경)는 애자일 이슈 규칙이 소유하며, 이 화면은 새 상태를 만들지 않는다.
      • 수락 기준 번호 보존 — 수락 기준은 문서에 적힌 번호를 그대로 유지한다. 화면이 다시 번호를 매기지 않는다 — 번호는 태스크·테스트가 참조하는 값이므로 화면에서 바뀌면 참조가 어긋난다.
      • 태스크 표기 — 문서의 Role 구분(백엔드 / 프론트엔드 / 앱)과 라인별 진행 상태·시각을 적힌 그대로 보여주고, 라인에 붙은 수락 기준 참조와 화면 영역 표기도 함께 보여준다. 상태를 화면에서 바꾸지 않는다.
      • 테스트 표기 — 성공과 실패(예외처리 포함) 구분을 유지해 나란히 보여준다. 문서의 구분을 화면에서 합치지 않는다.
      • 표시 항목의 원천 — 6항목은 모두 그 스토리 문서에서 읽는다. 상위 에픽·도메인에만 있는 정책을 스토리 본문에 끌어와 합치지 않는다.
      • 미정 — 확정 필요: 6항목 중 일부가 문서에 없는 스토리(예: 테스트 미작성)의 표기 방식은 요구사항에 근거가 없어 정의하지 않았다.
